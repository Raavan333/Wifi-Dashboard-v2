# RECOVERY DEFINITION

Recovered means:

```text
FAIL

followed later by

SUCCESS

for same MAC
```

Order matters.

Current implementation:

✅ Correct

Performance:

❌ Not acceptable

Current query:

~39 seconds

Current architecture:

❌ Computes on dashboard request

Required architecture:

Recovery state becomes part of aggregation.

Add to wifi_user_summary:

```sql
recovered_after_failure BOOLEAN

first_fail_timestamp TIMESTAMPTZ

last_success_after_fail TIMESTAMPTZ
```

Computed incrementally.

Dashboard should never scan 7.4M rows to compute recovery.
